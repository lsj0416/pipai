### 이슈 1. 마이페이지 데이터 절반만 LLM에 전달 [최우선] ✅ 구현 완료

**현재 문제**
업종·직원 수만 LLM 컨텍스트에 전달됨. 수집 개인정보 항목, 개인정보처리방침 보유 여부, 민감정보 유형 등 미전달

**변경 사항**
마이페이지에 입력된 전체 데이터를 LLM에 전달

```
전달 제외 항목 (개인정보 보호)
- 대표자명
- 사업자등록번호
- 담당자 연락처

전달 포함으로 변경할 항목 (기존 미전달)
- 수집 개인정보 항목 (일반/고유식별/민감/신용/위치)
- 수집 방법
- 이용 목적
- 처리 위탁·제공 현황
- 처리 환경 (운영 채널, CCTV 등)
- 안전조치 현황 (처리방침, CPO, 암호화 등)
- 마케팅·광고 현황
- 성장 시나리오
```

**구현 내용**
`LlmService.buildSystemPrompt()` — `annualRevenue`, `personalDataItems`, `hasPrivacyPolicy`, `sensitiveDataTypes` 4개 필드 추가 전달. null/blank 필드는 해당 줄 생략.

**담당자 정보 섹션 구조 변경**

마이페이지 섹션 2(담당자 정보) 항목을 회원가입으로 이동

```
마이페이지에서 제거:
- 담당자명
- 담당자 직함
- 담당자 이메일
- 담당자 연락처

→ 회원가입 시 입력 항목으로 이동
```

**회원가입 화면 변경**

```
기존 회원가입 항목:
- 이메일
- 비밀번호
- 이름

추가할 항목:
- 담당자 직함 (선택)
- 담당자 연락처 (필수)
- 약관 동의 (필수·선택 구분)
  ☐ 서비스 이용약관 (필수)
  ☐ 개인정보 수집·이용 동의 (필수)
  ☐ 마케팅 정보 수신 동의 (선택)
  ☐ 대화 내용 서비스 개선 활용 동의 (선택)
```

### 이슈 2. 대화 이력 LLM 미포함 [2순위] ✅ 구현 완료

**현재 문제**
매 메시지가 독립적인 단일 턴으로 처리됨. 직전 대화 내용이 LLM 컨텍스트에 없어 문맥 유지 불가

**변경 방향**
전체 대화 이력 전달은 토큰 비용 과다. 아래 두 가지 방식 병행

**방식 A. 현재 대화 이력 포함** ✅ 구현 완료
```
현재 대화의 메시지 이력 전체를 컨텍스트에 포함
(대화가 길어질 경우 최근 20개 메시지로 슬라이딩 윈도우 적용)
```

구현 내용:
- `ChatService.sendMessage()` — 메시지 저장 전에 이력 조회 (중복 방지)
- `LlmService.streamAnswer()` — history 파라미터 추가, OpenAI messages 배열에 USER/ASSISTANT 교대 포함
- ASSISTANT 응답의 면책 문구는 이력 포함 시 자동 제거

**방식 B. LLM 전용 메모 (히든 메모)** ✅ 구현 완료
마이페이지에 사용자에게 보이지 않는 메모 필드 추가.
LLM만 참고하는 누적 컨텍스트 저장소로 활용. 다른 대화창의 내용도 참조 가능.

```
저장 내용:
- 법적 판단을 받았던 내용 요약
  예: "2025-05-14: 고객 전화번호 수집 동의 없음 → 제15조 위반 가능성 진단"
- 문의글을 작성했던 내용 요약
  예: "2025-05-14: 기술지원 컨설팅 문의글 생성 (수집 동의 절차 관련)"

저장 방식:
- AI 답변 완료 시 백엔드에서 자동 요약 후 hidden_memo 필드에 append
- 사용자 UI에 노출 안 됨
- 다음 대화 시작 시 시스템 프롬프트 "이전 상담 이력 요약" 섹션에 자동 포함
```

구현 내용:
- `V7__add_hidden_memo.sql` — `company_profiles.hidden_memo TEXT` 컬럼 추가
- `CompanyProfile.appendHiddenMemo()` — 날짜 붙여 누적 append
- `ProfileService.appendHiddenMemo()` — 트랜잭션 처리
- `ChatService` — 스트리밍 완료 시 LLM으로 한 줄 요약 생성 후 비동기 저장

**DB 변경**
`company_profiles` 테이블에 컬럼 추가

```sql
ALTER TABLE company_profiles
ADD COLUMN hidden_memo TEXT DEFAULT '';
```

### 이슈 3. 시스템 프롬프트 고정 구조 [최후순위] ✅ 구현 완료

**현재 문제**
모든 질문에 동일 구조의 프롬프트 사용. 질문 유형(법령 해석 / 리스크 진단 / 절차 안내)에 따른 분기 없음

**구현 완료 (리스크 등급 강제 포함)**
모든 AI 답변에 아래 구조 강제 적용:

```
**리스크 수준:** [즉시 조치 / 확인 필요 / 양호] 중 하나
**근거 조문:** 법령명 제X조
**실무 권장사항:**
- 구체적 조치 방법
```

**구현 완료 — 질문 유형 3-way 분기**

```
질문 유형 분류 → 유형별 프롬프트 템플릿 적용 (LlmService.classifyQuestion)
- 법령 해석: 조문 원문 중심, 출처 명시 강조
- 리스크 진단: 기업 프로필 기반, 위반 가능성 수준 분류
- 절차 안내: 단계별 액션 아이템 형식
```

## 1. 마이페이지 구동 방식

### 1-1. 기본뷰 전환

기본뷰를 전체보기(읽기 모드)로 변경하고, 편집 버튼으로 편집 모드 전환

```
현재: 기본뷰 = 편집 모드
변경: 기본뷰 = 전체보기 → [편집] 버튼 클릭 시 편집 모드 전환
```

### 1-2. 첫 가입 온보딩 안내

마이페이지 미입력 상태 최초 진입 시 안내 문구 표시

```
- 모달 또는 상단 배너 형태
- "기업 정보를 입력하면 더 정확한 리스크 진단이 가능해요"
- [지금 입력하기] / [나중에 하기] 버튼
- 나중에 하기 선택 시 /chat으로 이동, 이후 진입마다 배너 표시 유지
```

### 1-3. 대화 ↔ 마이페이지 실시간 연동

**MVP 범위 (공모전 마감 전)**

AI가 대화 중 마이페이지 미입력 항목 감지 시

```
AI: "혹시 직원 수를 마이페이지에 등록해 두시겠어요?"
→ [예] 선택 시 해당 값 마이페이지 자동 저장
→ [아니오] 선택 시 현재 대화에서만 사용
```

답변 생성 시 필요한 기업 정보가 마이페이지에 없을 경우

```
AI가 역으로 질문하여 수집
예: "업종이 어떻게 되세요? 더 정확한 안내를 드릴 수 있어요."
```

**MVP 이후 범위**

대화 내용이 기존 마이페이지 데이터와 다를 경우 충돌 감지 및 확인

```
AI: "아까 직원이 3명이라고 하셨는데, 방금은 5명이라고 하셨어요.
     변경된 건가요, 아니면 다른 업체 얘기인가요?"
→ [변경됨] 선택 시 마이페이지 최신화
→ [다른 업체] 선택 시 현재 대화에서만 사용
```

### 1-4. 마이페이지 정보 읽기 오류

마이페이지 정보 일부만 AI 컨텍스트에 반영되는 버그
→ 리스크 판단 기준 문서 작성 완료 후 그에 맞춰 수정 예정
